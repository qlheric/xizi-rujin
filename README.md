# 中文 agent 可信评测 · zh-agent-eval

> 让中文 agent 的「好」能被**证明**，而不是被吹。

**核心**：任何中文 LLM / agent 接进来跑 golden 集，得到「能红断言 + 阴性对照 + 公开失败分析」的诚实报告。

---

## 为什么（真实摩擦）

中文 agent 生态的真实摩擦：**人人都说「成功率 95%」，但没人能复现、没人能证伪**。

本工具的对策（对标 ponytail 的「诚实 benchmark」内核、Ragas 的中文空位）：

1. **判据**：关键信息保真（数字 / 专名 / 核心断言，确定性 + 归一化）——能红、可复现，不是 LLM 自嗨；
2. **断言**：能红断言 + 阴性对照——必错 agent 必须被判显著差，证明评测有区分度、不是摆设；
3. **复核**：LLM-judge 复核同义变体（「找不到」=「未找到」）——辅助角色、结果公开；
4. **报告**：逐条失败案例 + 类型分类——诚实，不报「成功率 95%」。

---

## 用法

```bash
uv sync                                # 一键建环境
python -m eval.cli                     # mock 自检（零网络，验证闭环）
python -m eval.cli --engine deepseek   # 真实评测（deepseek/claude/gpt）
python -m eval.cli --engine claude --review   # 复核同义变体（辅助）
```

---

## benchmark（三模型实测，50 条中文问答，temperature=0）

| 模型 | 通过率（复核后） |
|---|---|
| deepseek-chat | 50/50（100%） |
| claude-opus-5-5 | 48/50（96%） |
| gpt-6-astra | 50/50（100%） |

复现：`uv sync` + 上表命令，任何人能重算。

---

## 诚实说明（判据的已知边界）

- **关键信息保真**是确定性判据，能抓硬错误（数字错 / 专名错 / 漏关键），但对「同义措辞」（低位 / 最低点）会误判——所以配 LLM-judge 复核，复核结果**逐条公开**。
- golden 集的 keys 设计原则：**只能是「核心且不可同义替换」的信息**（数字、专名、不可替代断言），不能是可被同义替代的词。
- 评测结果 = 50 条基础问答的实测，不是全场景能力结论。
